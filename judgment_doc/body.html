한 줄 정의와 결과 6종

DEFINITION
PASS = 버튼을 눌렀을 때 화면 값이 기대대로 바뀌고, 앱 로그에 있어야 할 기록이 남고, 에러 문구가 뜨지 않은 것.
FAIL = 이 중 하나라도 어긋났는데, 되돌린 뒤 한 번 더 해도 또 어긋난 것.
결과쉽게 말하면결함으로 셈표시창
PASS한 번에 기대대로 동작, 로그도 깨끗함—PASS
PASS(주의)화면은 정상인데 앱 로그에 처음 보는 종류의 에러가 찍힘아니오WARN
PASS(불안정)1차 실패 → 되돌리고 다시 하니 통과아니오WARN
FAIL1차·2차 둘 다 기대와 다름예FAIL
N/A확인할 버튼이 이 화면 구성에 원래 없음 (예: 4K 화면의 H06)—N/A
환경 오류제품이 아니라 실행 조건 문제로 확인을 못 함 (Admin 로그인·시뮬레이터 등)아니오SKIP
핵심재시도는 FAIL일 때만 1번. 두 번 모두 실패해야 FAIL이라서, 일시적인 응답 지연으로 FAIL이 나지 않습니다.

FAIL이 되는 6가지 경우

FAIL CONDITIONS
아래 중 하나라도 해당하면 그 시도는 실패입니다. 두 번 연속 실패하면 FAIL입니다.
#경우쉽게 말하면실제 메시지 예
F1값이 다름눌렀는데 숫자·글자가 규칙과 다르게 바뀜진행률 37% ≠ 기대 38% (N=15/40)
F2안 바뀜 (시간 초과)정해진 시간(5~10초, Recovery·홈 이동은 최대 45초) 안에 화면이 그대로'Enable Robot' 후 버튼이 'Disable Robot'(으)로 안 바뀜
F3로그 없음동작했으면 앱 로그에 남아야 할 기록이 5초 안에 안 찍힘로그에 'Servo ON' 없음
F4에러 문구새로 뜬 글자에 error·fail·오류·실패 등. "Safety zone error"는 제외 · 적용: H02·H03·H06·H08·녹화(C)·전체 클릭(K)의 모든 클릭 · 전체 클릭은 누른 뒤 앱이 꺼져도 FAIL레시피 적용: 에러 문구 표시 ['Load failed']
F5못 찾음·안 눌림있어야 할 버튼·메뉴가 없거나 눌러도 반응 없음⋮ 메뉴 항목 누락: ['Delete', 'Edit Recipe', …]
F6화면끼리 다름두 화면에 나온 같은 값이 서로 다름Solution Version v1.1.0 ≠ Home 표시 v1.1.1
F5는 먼저 의심부터. 제품 결함일 수도, 자동화가 화면을 못 다룬 것일 수도 있습니다. 실패 스크린샷에 해당 버튼이 보이는데 실패했다면 자동화 쪽 문제 → --mode mouse(실제 클릭)로 다시 돌려 비교합니다. 10-19 실행의 H06·R04 FAIL이 이 경우였습니다.

예시: H05 박스 [+] 한 번

EXAMPLE
레시피가 4층 × 층당 10박스 = 전체 40개, 지금 2층에 박스 5개가 쌓인 상태에서 박스 [+]를 누르면:
// 완료 박스 수 N = (층−1) × 층당 박스 + 현재 층 박스 누르기 전 N = (2−1)×10 + 5 = 15 진행률 = 15÷40 = 37.5% → 38% 누른 뒤 N = 16 → 기대: 층 2/4 · 박스 6/10 · 진행률 40% [−] 활성 (N>0) · [+] 활성 (N<40)
PASS
화면이 2층 · 6/10 · 40%, 버튼 두 개 모두 활성 → 기대와 전부 일치
→ 다시 [−]를 눌러 15로 되돌림
FAIL
화면이 2층 · 6/10 · 38%로 남음 (F1)
→ 되돌리고 다시 해도 38% → FAIL
메시지: 진행률 38% ≠ 기대 40% (N=16/40)
값은 이미지가 아니라 글자로 읽습니다. Windows 접근성 정보(UIA)로 버튼 이름·숫자·활성 여부를 읽어 계산값과 비교합니다. 창 크기나 겹친 창의 영향을 받지 않고, 실패 메시지에 "무엇이 무엇과 달랐는지"가 값 그대로 남습니다.

기대값은 어디서 오나 — 확인 근거 4종

ORACLE
1
화면 값의 규칙
누르기 전 값으로 누른 뒤 값을 계산해 비교. 예: 박스 [+] → N+1, 진행률 = N÷전체, [−]는 N=0일 때만 비활성 · 토글 Off → 그 열의 버튼 비활성
2
화면끼리 일치
시작 전에 Home 값(레시피 이름·층·박스·버전)을 기억해 두고 다른 메뉴의 같은 값과 비교. 예: Recipes의 In Use = Home 레시피 · Settings 버전 = Home 버전
3
앱 로그 기록
C:\Dr.Dart-Platform\logs\오늘날짜*.log에서 동작 직후 줄을 찾음. 예: Enable → Servo ON · 홈 이동 → 0506 · Recovery → 0511 · DO 출력 → setDigitalOutput 200 OK · Log 화면 최신 줄 = 파일 마지막 ModuleLog
4
에러 문구 금지
눌렀을 때 새로 나타난 글자에 error · fail · failed · exception · 오류 · 실패가 있으면 실패. 단 "Safety zone error"는 시뮬레이터 안전 설정 때문에 항상 떠서 제외
기억할 것기대값은 사양서 수치가 아니라 같은 화면의 규칙·다른 화면·로그에서 옵니다. 그래서 레시피가 바뀌어도 판정 기준을 고칠 필요가 없습니다.

"새 로그 에러" 가리는 법 — PASS(주의)

LOG CHECK
앱은 평소에도 에러 줄을 남깁니다(로그인 실패 시도, 서버 조회 실패 등). 그래서 에러가 있느냐가 아니라 처음 보는 종류냐로 봅니다.
STEP 1
항목 시작 때 로그 파일 끝 위치 기억
STEP 2
그 뒤 새 줄 중 [error] 줄만
STEP 3
숫자를 모두 #으로 → 에러 "종류"
STEP 4
기준 목록에 없으면 새 에러
// 원문 (로그 한 줄) [10:02:11.5][error][DP] [DataSyncManager] GET, status: 404, reason: 'Request failed with status code 404' // 종류(서명) — 숫자만 다른 같은 에러는 하나로 묶임 [DataSyncManager] GET, status: #, reason: 'Request failed with status code #'
기준 목록
baseline_errors.txt — 평소에도 찍히는 "정상 소음" 종류 (현재 10종)
새 에러가 정상 소음이면
approve_errors.bat 실행 → 목록에 추가 → 다음부터 PASS
※ 실행 전부터 있던 에러 줄은 보지 않습니다. 화면 확인이 PASS여도 새 에러가 있으면 PASS(주의)이고, 1차 실패 후 통과한 경우에는 PASS(불안정)이 우선합니다.

결과별로 할 일 · 판정하지 않는 것

ACTION
결과할 일
PASS없음
PASS(주의)리포트의 로그 줄 확인 → 평소 소음이면 approve_errors.bat, 처음 보는 오류면 이슈 검토
PASS(불안정)반복되면 elements.yaml의 speed를 낮춰 보고, 그래도 반복되면 제품 응답 지연 의심
FAIL메시지 → 스크린샷 → 화면 구조(UI 트리) 순서로 확인. 버튼이 보이는데 실패면 --mode mouse로 재확인, 화면이 실제로 틀렸으면 이슈 등록
환경 오류메시지의 원인(Admin 비밀번호, 시뮬레이터, 앱 연결)을 고친 뒤 다시 실행
실행 중 상태 표시창
항목 실행 중엔 ING → 항목이 끝나는 순간 그 결과(PASS·FAIL·WARN·N/A·SKIP)를 1초 표시 → 다음 항목에서 다시 ING. 제목 줄에 누적(예: 18/42 · 통과 11 · 실패 5 · 제외 1), 칩 색은 각 항목의 최종 결과(30개가 넘으면 오래된 칩부터 숨김)
판정하지 않는 것
응답 속도·성능화면 디자인·배치·색3D 뷰 그림 "Safety zone error" 배너실행 전부터 있던 로그 에러원상복구 성공 여부 (리포트에 따로 표시)
