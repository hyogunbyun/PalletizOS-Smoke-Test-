왜 스모크 테스트부터 — 관문(Gate) 역할

WHY
스모크 테스트 = "이 빌드가 매뉴얼 테스트를 시작할 만큼 기본이 살아 있는가"를 사람 대신 빠르게 확인하는 단계
1
깨진 빌드에 매뉴얼 공수를 쓰지 않음 — 메뉴가 안 열리거나 값이 틀리면 앞쪽 기본 항목(30개, 항목 합계 약 5분)에서 바로 드러납니다. 매뉴얼 테스트를 몇 시간 하다 발견하는 일을 막습니다.
2
매번 같은 기준 — 같은 42개 항목, 같은 판정 규칙. 사람마다·날마다 확인 범위가 달라지지 않습니다.
3
증거가 남음 — 항목별 결과·실패 메시지·스크린샷·화면 구조가 리포트로 자동 저장되고, 버전별 이력이 쌓입니다.
4
사람은 어려운 쪽에 집중 — 반복 확인은 자동화가, 사양 확인·예외 상황·사용성은 매뉴얼 테스트가 맡습니다.
한계도 분명히스모크는 넓고 얕게 봅니다. PASS가 "결함 없음"을 뜻하지 않으며, 매뉴얼 테스트를 대신하지 않습니다.
3

구성과 동작 원리

HOW IT WORKS
1 · 준비
가상 제어기 시뮬레이터(Docker) 자동 기동
2 · 연결
Dr.Dart 앱 실행 → 제어기 연결 → PalletizOS 진입
3 · 항목
항목마다 실행 → 판정 → 원상복구
4 · 결과
HTML 리포트 · 이력 · 시작 계정 복귀
특징내용
백그라운드 방식마우스·키보드를 쓰지 않고 Windows 접근성 정보(UIA)로 버튼을 찾아 누름 → 실행 중 다른 업무 가능
좌표가 아닌 객체버튼 이름·종류로 찾음 → 창 크기·해상도가 달라도 동작, 값은 글자로 읽어 비교
재시도 1회실패하면 원래대로 되돌린 뒤 한 번 더 → 일시적 지연으로 FAIL 나지 않음
원상복구바꾼 값(토글·레시피·층/박스·Enable·계정)을 항목마다 시작 상태로 되돌림
로그 감시앱 로그에 처음 보는 종류의 에러 → "주의" · 멈춤·앱 재시작 원인은 events.log에 기록
FAIL → JIRA리포트의 이슈 등록 → 미리보기 → TER 버그 (스크린샷·앱 로그 첨부)
CI/CD 연계GitHub 릴리스 감시 → 설치된 버전보다 높으면 다운로드 → Install from File 자동 설치 → 스모크
Python + pywinauto(UIA) · 화면 문구는 elements.yaml 한 곳 · Admin 비밀번호는 Windows 자격 증명에만 저장 (파일·로그에 남기지 않음)

실행 방법 — 바탕화면 아이콘 3개

HOW TO RUN
파일용도
PalletizOS_smoke.bat스모크 테스트 실행 — 설치한 버전 입력(엔터=생략) 후 무인 진행, 끝나면 리포트가 열림
PalletizOS_record.bat시나리오 녹화 — 앱에서 직접 눌러 새 항목 추가
PalletizOS_scenarios.bat녹화 시나리오 편집·삭제·하나만 실행
실행 중 화면 — 앱 오른쪽 위 상태 표시창
1
배지 ING → 항목이 끝날 때마다 PASS·FAIL 1초 표시, 제목 줄에 누적 집계
2
칩 색 = 결과 (많으면 오래된 칩부터 숨김) · 칩을 두 번 누르면 그 항목만 바로 다시 실행
3
■ 자동화 종료(0.6~3초 사이 두 번) = 원래 상태로 되돌린 뒤 멈춤 · 끝나면 리포트를 열고 콘솔은 15초 뒤 자동 종료
처음 한 번만
Dr.Dart-Platform 설치 · Rancher Desktop(Docker) 실행 · setup.bat으로 Python 환경 생성 · 첫 실행 때 Admin 비밀번호 입력(이후 자동) · JIRA 등록은 jira_setup.bat · 자동 설치는 github_setup.bat(읽기 전용 토큰, 감시기는 로그온 때 자동 시작)
6

판정 결과 → 다음 단계

DECISION
전체 판정뜻다음 단계
통과모든 항목 PASS (또는 해당없음)매뉴얼 테스트 시작
통과(주의)화면은 정상, 새 로그 에러 또는 재시도 후 통과리포트의 로그 줄 확인 → 소음이면 승인(approve_errors.bat) → 매뉴얼 테스트 시작
보류FAIL 1개 이상FAIL 분석 → 제품 결함이면 이슈 등록, 매뉴얼 테스트 보류 · 화면 변경이면 자동화 갱신 후 재실행
재실행 필요환경 오류로 일부 항목 확인 못 함환경 조치 후 스모크 재실행 (결함 아님)
중단사용자가 종료함다시 실행
항목 하나의 판정
PASS = 화면 값이 기대대로 바뀌고, 로그가 남고, 에러 문구가 없음 · FAIL = 되돌린 뒤 한 번 더 해도 어긋남 · 해당없음 = 컨트롤이 원래 없음 · 환경 오류 = 실행 조건 문제
FAIL 분석 요령스크린샷에 해당 버튼이 보이는데 실패했다면 자동화 쪽 문제일 가능성 → --mode mouse로 다시 돌려 비교
